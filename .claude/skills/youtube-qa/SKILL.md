# YouTube 대본 → Q&A 변환 (서브에이전트 전용)

너는 **영상 한 편**을 담당한다. 이 대본은 너의 컨텍스트에만 존재하며, 네가 끝나면 사라진다.
메인 에이전트에게 대본 내용을 되돌려 보내지 마라 — 파일 경로와 숫자만 반환한다.

## 받는 것

| 항목 | 예 |
|------|-----|
| `video_id` | `dQw4w9WgXcQ` |
| 대본 경로 | `output/transcripts_raw/{video_id}.txt` |
| `caption_type` | `auto` 또는 `manual` |
| `lang` | `ko`, `en`, … |
| `char_count` | `9,240` |
| 영상 제목·채널명 | `왜 데이터센터가 …ㅣ황수욱 연구원` / `메리츠증권` |
| 파이썬 | `.venv\Scripts\python.exe` |
| 스크립트 폴더 | `.claude\skills\youtube-qa\scripts` |

대본은 `[mm:ss]` 구간 마커가 ~60초마다 붙어 있다. 이 마커가 딥링크의 근거다.

**제목·채널명은 표기 복원의 근거다.** 자동생성 자막이 출연자 이름·회사명을 틀렸을 때
(`황수욱` → `황숙`, `메리츠증권` → `메리치권`) 제목에 정답이 있으면 그쪽을 따른다.
같은 영상의 메타데이터이므로 외부 지식 추가가 아니다. 제목에도 근거가 없으면 들린 대로 둔다.

## 반환하는 것

```
video_id, 아웃라인 경로, Q&A 임시 파일 경로, qa_count, 커버리지 판정(pass/fail + 사유)
```

**절대 하지 않는 것:** 최종 md 작성, frontmatter 생성, `INDEX.md`·`state.json` 수정,
`output/qa/`에 파일 쓰기. 전부 `save_qa.py`가 한다.

---

## 최상위 원칙

> **품질 우선, 낭비만 제거.** 토큰을 아끼려고 Q를 줄이거나 A를 짧게 쓰지 마라.
> 절약은 "불필요한 것을 컨텍스트에 올리지 않는다"로만 정의한다.

---

## Step 3.5 — 주제 아웃라인 추출

대본을 훑어 **주제 목차**를 만든다. 이 아웃라인은 세 곳에 쓰인다:
① Step 4의 분할 기준 ② Step 4.5의 커버리지 정답지 ③ INDEX.md의 주제 열.

### 길이에 따른 분기

```
char_count ≤ 10,000  →  대본 전체를 한 번에 읽고 아웃라인 생성
char_count > 10,000  →  계층 처리
                        ① 대본을 ~8,000자 구간으로 분할 (반드시 마커 줄 경계)
                        ② 구간별로 아웃라인 생성
                        ③ 이어붙인 뒤, 경계에서 끊긴 같은 주제만 병합
                        ※ 병합은 인접 경계에서만. 멀리 떨어진 주제는 합치지 않는다
```

계층 처리를 하더라도 **영상 길이를 이유로 스킵하지 않는다.** 길면 비용이 길이에 비례해
늘어날 뿐이며, 이는 의도된 트레이드오프다.

### 주제 하나의 크기

화자가 "다음으로 넘어가는" 지점마다 하나씩 끊는다. 실무 기준:

- 대략 **1~5분에 한 항목**. 10분 넘게 한 주제로 묶였다면 하위 전환점을 놓친 것이다.
- 9,000자 대본이면 보통 **6~12개**가 나온다.
- 인사·클로징도 하나의 항목으로 잡는다 (누락 판정을 정확히 하기 위해).

### 출력 형식 — `output/outlines/{video_id}.md`

```markdown
- [00:00] 영상 소개와 오늘 다룰 주제
- [01:20] PR 담당자가 흔히 겪는 세 가지 문제
- [05:40] 첫 번째 문제 — 메시지 일관성
- [11:05] 두 번째 문제 — 채널별 톤 차이
```

- 각 줄은 `- [mm:ss] 주제명` 형식만. 다른 텍스트·헤더·번호를 넣지 마라.
- 시점은 **대본에 실제로 있는 마커 값**을 쓴다. 만들어내지 않는다.
- 주제명은 한국어. 영어 대본이어도 한국어로 쓴다.
- 시간 순서대로. 1시간 넘는 영상은 분이 60을 넘어간다(`[72:10]`) — 그대로 쓴다.

### 검증 (필수)

```bash
.venv\Scripts\python.exe .claude\skills\youtube-qa\scripts\verify.py outline <video_id>
```

`ok: false`면 `problems`를 읽고 아웃라인을 고쳐 다시 쓴 뒤 재검증한다.
**재시도는 1회.** 두 번째도 실패하면 Q&A로 진행하지 말고 `fail` 사유와 함께 반환한다.

## Step 4 — 주제 블록별 Q&A 변환

아웃라인의 주제 경계로 대본을 자르고, **블록마다 같은 지침으로** Q&A를 만든다.
고정 글자 수로 자르지 마라 — 주제 경계로 자르는 것이 이 설계의 핵심이다.

```
주제 블록 1 (00:00~01:20) ─┐
주제 블록 2 (01:20~05:40) ─┼─▶ 블록별 Q&A ─▶ 이어붙여 하나의 본문
주제 블록 3 (05:40~11:05) ─┘   ※ Q 번호는 신경 쓰지 마라 (save_qa.py가 재부여)
```

한 블록이 8,000자를 넘으면 그 블록만 문장 경계에서 2분할한다. 이때도 분할 지점은
하위 주제 전환점을 우선 따른다.

### 변환 규칙

| # | 규칙 |
|---|------|
| 1 | **대본 내용에만 의거한다.** 표기 복원은 허용, 내용 추가는 금지 (아래 경계선 표) |
| 2 | **설명 위주 영상이라도 Q를 능동적으로 만든다.** "~란 무엇인가?", "~의 핵심 포인트는?", "~와 ~의 차이는?" |
| 3 | **의미 단위 무손실.** 인사말·군더더기·반복만 제거하고 설명 내용은 전부 담는다 |
| 4 | **영상 흐름 순서를 유지한다.** 앞뒤로 흩어진 같은 주제를 하나의 Q로 통합하지 않는다 |
| 5 | **각 Q에 시작 시점을 부여한다.** 그 내용이 속한 구간 마커 값을 쓴다 |
| 6 | **A는 대본의 표현을 살리되 읽기 쉽게 정돈한다.** 화자의 어투·비유·강조는 보존한다 |
| 7 | **항상 한국어.** 영어 대본이어도 Q와 A는 한국어로 쓴다 |

### 목표 밀도 — 지켜야 하는 수치

| 기준 | 값 |
|------|-----|
| Q 개수 | 대본 **9,000자당 15~25개** |
| A 길이 | 각 **3~8줄** |
| 최종 본문 분량 | 원문 대비 **60~70%** |

9,000자를 Q 5개로 요약하는 것은 **실패**다. "핵심만 추리는" 작업이 아니라
"의미 단위를 잃지 않고 읽기 좋게 재구성하는" 작업이다.

### 출처 한정의 경계선

| 구분 | 판정 | 예시 |
|------|------|------|
| 오탈자·음차 표기 교정 | **허용** | `피이알` → `PR`, `깃헙` → `GitHub` |
| 문장부호·띄어쓰기 삽입 | **허용** | `그래서 이제 그러니까 담당자가` → `그래서 이제, 담당자가` |
| 필러(어·음·뭐냐) 제거 | **허용** | — |
| 대본에 없는 정의·배경 설명 추가 | **금지** | "PR"만 말했는데 "PR(Public Relations, 홍보)"로 풀어 쓰기 |
| 대본에 없는 예시·수치·출처 추가 | **금지** | — |
| 화자 주장의 보완·반박·평가 | **금지** | — |

### caption_type별 추가 지침

| caption_type | 적용 |
|--------------|------|
| `auto` | 이 대본은 자동생성 자막이라 문장부호가 없고 고유명사·숫자 오인식이 있다. 문맥으로 표기를 복원하되, 대본에 없는 내용을 추가하지 마라. 확신이 안 서는 고유명사는 들린 대로 두는 편이 낫다 |
| `manual` | 복원 지침을 적용하지 마라. 원문 표기를 신뢰하고 그대로 인용한다. 필러 제거와 줄바꿈 정리만 한다 |

### 출력 형식 — `output/.tmp/{video_id}_qa.md`

Q&A 본문만 쓴다. frontmatter·제목 헤더·`## Q&A`를 넣지 마라.

```markdown
**Q1. 영상에서 다루는 핵심 질문/주제 1** · [00:00](https://youtu.be/{video_id}?t=0)

A. 해당 부분의 내용을 대본 기반으로 상세히 정리한다. 3~8줄.

**Q2. 핵심 질문/주제 2** · [02:13](https://youtu.be/{video_id}?t=133)

A. 해당 내용 정리.
```

- Q 번호는 1부터 붙이되 정확할 필요는 없다. `save_qa.py`가 순차 재부여한다.
- `?t=` 값(초)도 `save_qa.py`가 `[mm:ss]` 표시값에서 다시 계산한다. **표시되는 `[mm:ss]`가
  정확한지에만 신경 써라.**
- 예시는 `references/qa_examples.md` 참조.

## Step 4.5 — 커버리지 점검

### ① 기계 점검

```bash
.venv\Scripts\python.exe .claude\skills\youtube-qa\scripts\verify.py qa <video_id>
```

`density_per_9k`, `body_chars` 비율, `uncovered_topics`(Q가 하나도 없는 아웃라인 구간),
Q 시점 순서 위반을 잡아낸다.

### ② 의미 대조 (기계 점검이 통과해도 반드시 한다)

아웃라인을 정답지로 놓고, **항목 하나하나에 대응하는 Q&A가 있는지** 대조한다.
"그 구간에 Q가 있다"가 아니라 **"그 주제에서 화자가 설명한 내용이 A에 담겼는지"**를 본다.

각 아웃라인 항목을 `충족 / 얕음 / 누락` 으로 판정한다.

- **충족** — 해당 주제의 설명이 온전히 들어갔다
- **얕음** — Q는 있으나 대본의 설명 절반 이상이 빠졌다
- **누락** — 대응하는 Q가 없다

### ③ 보충 (1회)

`얕음`·`누락`이 하나라도 있으면, **그 구간의 대본만 다시 읽고** Q&A를 보충해
`output/.tmp/{video_id}_qa.md`를 시간 순서에 맞게 다시 쓴다. 다른 구간은 건드리지 마라.
보충 후 ①②를 한 번 더 돌린다.

**보충은 1회.** 재실패하면 `fail`로 반환한다 — 이 영상은 `output/qa/`에 파일을 만들지 않는다.

## 반환 형식

메인 에이전트에게 아래만 돌려준다. 대본이나 Q&A 본문을 붙이지 마라.

```
video_id:   dQw4w9WgXcQ
outline:    output/outlines/dQw4w9WgXcQ.md  (주제 9개)
qa_file:    output/.tmp/dQw4w9WgXcQ_qa.md
qa_count:   19
coverage:   pass
density:    9,000자당 18.5개 / 본문 원문 대비 64%
notes:      (있으면 한 줄)
```

실패 시:

```
video_id:   dQw4w9WgXcQ
coverage:   fail
reason:     아웃라인 검증 2회 실패 — 시점 형식 파싱 불가
```
