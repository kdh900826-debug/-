# Q&A 변환 예시

SKILL.md의 지침이 실제로 어떻게 적용되는지 보여주는 참고 자료.
분량감·표기 복원 범위·딥링크 처리를 이 예시에 맞춘다.

---

## 1. 자동생성 자막(ko, auto) → Q&A

### 대본 원문 (구간 마커 포함)

```
[03:00] 자 그러면 이제 두 번째 문제로 넘어가 볼게요 어 채널별 톤 차이라는 건데 이게 뭐냐면
저희가 보도자료 쓸 때랑 인스타 올릴 때랑 링크드인 올릴 때 톤이 다 달라야 되잖아요 근데
문제는 뭐냐면 담당자가 한 명일 때는 그래도 좀 일관성이 있는데 세 명 네 명 되면 어 이게
사람마다 인스타 톤을 다르게 잡아요 누구는 되게 친근하게 쓰고 누구는 좀 뭐랄까 딱딱하게
쓰고 그래서 결국 밖에서 보는 사람 입장에서는 이 브랜드가 도대체 어떤 성격인지를 모르겠는
거예요
[04:00] 그래서 저희가 했던 게 톤 가이드를 만드는 건데 그냥 만들면 아무도 안 봐요 진짜
아무도 안 봅니다 저희도 처음에 20페이지짜리 만들었다가 완전히 실패했거든요 그래서 두
번째로 만들 때는 채널별로 한 장씩 딱 A4 한 장 그리고 그 안에 예시 문장을 좋은 예 나쁜 예
이렇게 세 쌍씩 넣었어요 그랬더니 이제 사람들이 보기 시작하더라고요
```

### 변환 결과

```markdown
**Q5. 채널별 톤 차이는 왜 문제가 되는가?** · [03:00](https://youtu.be/XXXXX?t=180)

A. 보도자료, 인스타그램, 링크드인은 각각 톤이 달라야 하는 게 정상이다. 문제는 담당자가
여러 명일 때 생긴다. 한 명이 맡을 때는 그래도 일관성이 있는데, 세 명 네 명이 되면 같은
인스타그램 채널인데도 사람마다 톤을 다르게 잡는다. 누구는 친근하게 쓰고 누구는 딱딱하게
쓴다. 결국 밖에서 보는 사람 입장에서는 이 브랜드가 어떤 성격인지 알 수 없게 된다.

**Q6. 톤 가이드는 어떻게 만들어야 실제로 쓰이는가?** · [04:00](https://youtu.be/XXXXX?t=240)

A. 그냥 만들면 아무도 안 본다. 화자의 팀도 처음에 20페이지짜리를 만들었다가 완전히
실패했다. 두 번째로 만들 때는 분량을 줄였다 — 채널별로 A4 한 장씩, 그 안에 예시 문장을
좋은 예와 나쁜 예 세 쌍씩 넣었다. 그러자 사람들이 보기 시작했다.
```

### 이 예시가 보여주는 것

| 항목 | 적용 |
|------|------|
| 필러 제거 | `자 그러면 이제`, `어`, `뭐냐면`, `뭐랄까`, `진짜` 삭제 |
| 문장부호 복원 | 끊어진 구어를 문장으로 정리 |
| 내용 보존 | "20페이지 실패", "A4 한 장", "좋은 예/나쁜 예 세 쌍" 전부 살아 있음 |
| 내용 추가 금지 | 톤 가이드의 일반론이나 다른 사례를 끌어오지 않음 |
| 화자 어투 보존 | "아무도 안 본다"의 단정적 어조 유지 |
| 딥링크 | 그 내용이 속한 구간 마커 `[03:00]`, `[04:00]` 그대로 채택 |
| 분량 | 원문 2개 블록 → Q 2개, A 각 4~5줄 (원문 대비 약 65%) |

## 2. 영어 수동 자막(en, manual) → 한국어 Q&A

### 대본 원문

```
[12:00] The thing most teams get wrong about retrospectives is treating them as a
status meeting. You go around the room, everyone says what they did, and then you
run out of time. A retrospective is not a report. It's a decision-making meeting.
If you leave without a decision that changes what you do next week, you wasted an hour.
```

### 변환 결과

```markdown
**Q14. 대부분의 팀이 회고에서 저지르는 실수는 무엇인가?** · [12:00](https://youtu.be/XXXXX?t=720)

A. 회고를 상태 보고 회의처럼 다루는 것이다. 돌아가면서 각자 무엇을 했는지 말하다 보면
시간이 끝나 버린다. 회고는 보고가 아니라 의사결정 회의다. 다음 주에 하는 일을 바꾸는
결정 없이 회의를 나왔다면, 한 시간을 낭비한 것이다.
```

### 이 예시가 보여주는 것

- 원어(영어) 자막을 읽고 **Q와 A 모두 한국어**로 작성한다. YouTube 자동번역 자막은 쓰지 않는다.
- `manual` 자막이므로 **표기 복원 지침을 적용하지 않는다.** 원문이 이미 정제되어 있다.
- 직역이 아니라 자연스러운 한국어로 옮기되, "보고가 아니라 의사결정 회의"라는 대비 구조와
  "한 시간을 낭비한 것"이라는 단정적 마무리를 그대로 살린다.

## 3. 흔한 실패 사례

### ❌ 과도한 압축

```markdown
**Q5. 톤 관리는 어떻게 하는가?** · [03:00](...)

A. 채널별 톤 가이드를 A4 한 장으로 만들면 좋다.
```

두 개 블록(약 600자)을 두 줄로 줄였다. "담당자가 늘면 일관성이 깨진다"는 원인 분석,
"20페이지는 실패했다"는 실패 경험, "좋은 예/나쁜 예 세 쌍"이라는 구체적 방법이 전부
사라졌다. **의미 단위 무손실 위반.**

### ❌ 내용 추가

```markdown
A. ... 채널별 톤 가이드를 A4 한 장으로 만든다. 일반적으로 톤 가이드에는 브랜드
보이스, 금지 표현, 이모지 사용 규칙이 포함된다.
```

뒷문장은 대본에 없다. **출처 한정 위반.**

### ❌ 주제 통합

영상 03:00과 25:00에서 각각 언급된 "톤" 이야기를 하나의 Q로 합쳤다.
**영상 흐름 순서 유지 위반** — 각각 별도의 Q로 둔다.

### ❌ 시점 조작

대본에 `[03:00]`, `[04:00]` 마커만 있는데 Q에 `[03:27]`을 썼다.
마커에 없는 시점을 만들어내면 딥링크가 어긋난다. **구간 마커 값만 쓴다.**
